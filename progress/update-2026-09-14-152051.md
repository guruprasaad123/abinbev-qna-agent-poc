# Progress Update — 2026-09-14 15:20

## New: optional local-embedding semantic retrieval signal (hybrid: BM25 + metadata + embeddings)

Implements the follow-up `docs/DESIGN_DECISIONS.md` §6 had flagged since the original BM25
decision. Checked, not assumed, before choosing an approach: the configured LLM gateway
(`tokenharbor.ai`) has zero embedding models among its 34 available models, so a hosted
embeddings API wasn't an option without a second provider account. Chose local (`fastembed`,
`BAAI/bge-small-en-v1.5`, 384 dims) instead, given this project targets a Streamlit Community
Cloud free-tier deploy (1GB RAM, 1 CPU) and a second paid account wasn't wanted.

**Real numbers measured directly, not estimated**, before committing to the design:
- Cold boot (first run, downloads ~196MB from HF Hub): 11.6s; warm boot (cached): 0.46s
- Per-document/query embedding: ~4-5ms (negligible vs. this system's 5-90s+ LLM call latencies)
- **Process RSS: ~332MB with the model loaded vs. ~44MB for the rest of the app** -- the
  embedding model alone is ~3x the footprint of everything else combined. Real, meaningful
  (~a third of the 1GB budget), genuine headroom remains (~688MB), verified not assumed.

**Built:**
- `src/tools/embedding_tool.py`: `embed_texts()`/`cosine_similarity()`/
  `load_cached_document_embeddings()`, all gracefully degrading (return `None`, never raise) if
  `fastembed` isn't installed, the cache is missing, or the model fails to load.
- `scripts/generate_embeddings.py`: precomputes + caches the 15-document corpus's embeddings to
  `data/unstructured/embeddings_cache.json` (committed, like `ab_inbev.db` -- 124KB, small).
  Only the query gets embedded live, per search call, never the (fixed) corpus.
- `src/tools/retrieval_tool.py`: `DocumentIndex.search()` now blends BM25 + metadata/recency +
  an optional semantic score. When embeddings are available, EVERY document is scored (not just
  BM25's pre-filtered top-k*3), since the whole point is surfacing a paraphrase match BM25
  would score zero on and never even consider.
- `tests/test_pipeline.py::TestEmbeddingGracefulDegradation`: 6 new offline tests (cosine math,
  missing/mismatched cache handling, and the real end-to-end guarantee that search() works
  without fastembed installed at all) -- the whole offline suite was run with plain `python3`
  (fastembed genuinely absent) to prove this isn't just tested in principle. 40/40 pass.

**A real before/after example** (not synthetic): "Are there markets where fewer people are
drinking beer this year" -- BM25-only ranked the one document with actual country-level volume
decline data (DOC-011) *outside* the top 3 entirely; adding the semantic signal correctly
pulled it to rank 3. Verified directly, both ways, via plain `python3` (BM25-only) vs. `uv run`
(fastembed available) on the identical query.

**Caught and fixed a real deployment bug before it shipped**: initially added `fastembed` to
`requirements.txt` directly -- but a flat requirements.txt has no concept of "optional" the way
`pyproject.toml`'s extras do, and Streamlit Community Cloud installs everything in it
unconditionally. That would have force-installed the ~288MB model on every deploy regardless of
intent, defeating the entire point of making this opt-in for a RAM-constrained target. Fixed:
removed it from `requirements.txt`, added a separate `requirements-embeddings.txt` (not
auto-installed by anything), documented how to opt in deliberately. Verified the fix directly:
`requirements.txt` now lists exactly the same 7 packages as before this change.

**Documented thoroughly, as asked**: `docs/DESIGN_DECISIONS.md` §6 rewritten in full (why
local not hosted, the real measured numbers, the graceful-degradation guarantee, the real
before/after example, and cons stated plainly: breaks pure-offline retrieval, new HF Hub
reachability dependency, CPU contention risk if sub-agent parallelization is ever added,
small-corpus diminishing returns, one more model to keep pinned). `docs/CAPABILITY_MAPPING.md`
#12 updated. README's dependency/Quickstart/repository-structure sections updated to explain
the opt-in path clearly for both local dev and Streamlit Cloud deployment.

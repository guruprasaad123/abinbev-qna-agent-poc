# Progress Update — 2026-09-12 20:00

## UI polish pass (ui/app.py rewrite)

User shared a screenshot of a differently-branded reference UI (dark theme, sidebar with
Active Context Filters / Session Telemetry / Call Profile by Component / Sample Questions,
a tabbed "Developer Mode: Reactive Agent Workflow & Tool Inspection" panel, a router badge,
clickable follow-up suggestions) and asked for the structural/UX ideas to be adopted --
explicitly not asked to pixel-match its colors/branding, or its fictional dataset claims
(brand/country-level data, "BEES marketplace", "8 megabrands") which do not reflect what this
system's real, zone-level-only AB InBev dataset actually has.

**Adopted (own implementation, not a clone):**
- `.streamlit/config.toml`: dark theme, amber/orange accent.
- Sidebar: title block, dev-mode toggle, **Active Context Filters** (badge chips rendered
  from `orchestrator.memory.active_filters`), **Session Telemetry** (4 `st.metric` cards from
  `GLOBAL_USAGE.summary()`), **Call Profile by Component** (expander, table breakdown by
  caller), **Sample Questions** (buttons covering a normal query, a comparison, the
  Brazil-rolls-up-to-zone hierarchy-fallback case, a document-retrieval query, and a genuine
  SQL-injection-attempt string to demonstrate the real SQL safety layer).
- Main area: chat avatars (🍺 assistant; 🚨 for a message matching a SQL-injection-ish
  pattern, cosmetic only -- the real safety boundary is unconditional and server-side in
  `src/tools/sql_tool.py` regardless of this heuristic), a router badge showing the model that
  actually served the last synthesis call (reads real usage events, reflects a fallback if one
  fired), follow-up suggestions as clickable buttons (not just static text) that resubmit as
  the next question.
- Persistent, tabbed developer-mode inspector per answer (`_render_dev_panel`): "1. NLU
  Intent" / "2. Sub-Agent Dispatch" / "3. Tool Outputs" / "4. Validation & Guardrails" /
  "5. Turn Telemetry" -- all populated from the real `on_step` trace and a per-turn slice of
  `GLOBAL_USAGE.events` (captured via a before/after index diff, so it's this turn's actual
  calls, not the cumulative session).
- Fixed a real bug introduced during the first draft: follow-up-suggestion buttons were only
  clickable on the turn that had just answered -- on any subsequent rerun (Streamlit re-executes
  the whole script per interaction) they silently degraded to plain-text captions. Fixed by
  extracting a shared `_render_followups()` helper keyed by a stable per-turn counter
  (`st.session_state.turn_counter`), used identically by the live render and history replay.

## What was found and fixed this session

1. **Notebook was built entirely against the mock LLM**, not a real model, despite a working key
   being configured in `.env`. Cause: `scripts/build_notebook.py` never loaded `.env` (only
   `scripts/chat_cli.py` did). Every "AGENT:" answer in all ~28 code cells was the literal
   placeholder string, not a real generated answer.
   - Fix: added the same `dotenv.load_dotenv()` call to `scripts/build_notebook.py`.

2. **Real crash on real-model output shape.** `src/orchestrator.py::_run_nlu` only guarded
   against invalid JSON syntax (`json.JSONDecodeError`), not against valid-but-wrong-shaped JSON.
   The configured model (`deepseek-v4-flash:free` via a custom `LLM_BASE_URL` gateway) sometimes
   wraps its classification response in a `[...]` array instead of a bare `{...}` object, which
   parses fine but is a `list`, and `list.setdefault(...)` crashed the whole run.
   - Fix: `_run_nlu` now unwraps a single-element list-of-dict, and falls back to the safe
     default for anything that isn't a dict.

3. **Demo script premise mismatch.** `scripts/build_notebook.py`'s canned question list asked
   "What drove that growth?" immediately after a turn showing South America revenue had actually
   *declined* 2024→2025. The agent's answer pulled in unrelated data from an earlier, unrelated
   section instead of catching the false premise.
   - Fix: reworded the canned question to "What drove that change?" (neutral, matches the data).
   - Noted as a real (minor) product behavior gap either way: the agent doesn't currently push
     back when a follow-up's premise contradicts prior evidence.

4. **Reasoning leakage / truncation.** On one rerun, the synthesis call returned the model's raw
   scratch reasoning ("may be a follow-up to an answer that stated... Need answer: ...") as the
   final answer, because the reasoning-style free model spent its `max_tokens` budget thinking
   before writing the actual answer and got cut off mid-thought.
   - Fix: raised synthesis `max_tokens` from 900 to 1600 in `src/orchestrator.py`.
   - Fix: added a proper truncation guard in `src/llm_client.py` for both `AnthropicLLMClient`
     and `OpenAILLMClient` — if the API reports the response was cut off by the token cap
     (`stop_reason == "max_tokens"` / `finish_reason == "length"`), it retries once automatically
     with double the token budget (capped at 4000) instead of silently returning the truncated
     fragment as if it were the final answer.

5. **Comparison follow-ups silently dropping the entity under discussion.** In a long
   multi-turn conversation, "How does that compare to Middle Americas?" (with South America as
   the active context from the prior turn) produced a comparison of Middle Americas vs. North
   America vs. Asia Pacific — omitting South America, the actual subject, entirely. Root cause:
   the current turn's NLU-extracted entities (not the merged active-filters context) were passed
   to the structured sub-agent, so if the model didn't explicitly re-state the zone already in
   focus, it was silently lost.
   - Fix: for `comparison`-intent turns, `src/orchestrator.py::handle_turn` now explicitly
     injects the prior active zone/country/brand into the current turn's entities before calling
     sub-agents, rather than relying on the model to correctly resolve "that" from prose context
     alone.

All 18 offline tests (`tests/test_pipeline.py`) still pass after every fix.

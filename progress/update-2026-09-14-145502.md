# Progress Update — 2026-09-14 14:55

## New: single-page visual HTML test report, + wired to auto-regenerate

User asked for a single HTML page showing all test status visually, without re-running the
expensive live LLM suite. Built `scripts/build_test_report.py` +
`scripts/_test_report_template.html` -> `reports/capability_test_report.html`, a self-contained
(no external deps besides Google Fonts, with real fallbacks) local file, not a hosted link,
consistent with the notebooks/docs already being repo-committed deliverables.

**Design treatment** (utilitarian dashboard, not editorial -- loaded `artifact-design` skill
first): cool slate neutrals with a burnished amber-copper accent kept separate from semantic
pass/fail colors; Fraunces (display, restrained) + IBM Plex Sans (body) + IBM Plex Mono
(tabular numerals for costs/latencies/case IDs) as the type system; full light/dark token
structure per the skill's three-state pattern.

**Content**: stat tiles (25 capabilities, 185/185 cases, 100% pass, $0.2934 cost, 34/34 offline
tests) -> 6 cluster cards each with a pass-rate bar drawn to scale -> a searchable/filterable
accordion of all 25 capabilities, each expanding to its real cases/questions/answers -> footer
with the real models used. Only the free/instant offline suite is re-run to produce this page;
the 185 live-case numbers are read from the already-captured `tests/live/reports/cap*.json`.

**Hardened one real risk**: escaped `</script` inside the embedded JSON data, since case
answers are arbitrary real LLM output that could in principle contain that literal substring
and corrupt the page on a future rebuild -- verified safe this time, guarded regardless.

**Then wired it to auto-regenerate**: user asked whether running the tests already produced
this page -- it didn't; it was a separate manual step. Fixed by having
`scripts/run_live_capability_tests.py` call the report builder itself at the end of every run
(any `--capability`/`--case` scope), non-fatally (a failure there doesn't affect the actual test
run's own pass/fail result). Required adding the `scripts/` directory itself to `sys.path`
(previously only the repo root was inserted) so `import build_test_report` resolves regardless
of how the script is invoked. Verified end-to-end with a real single-case run: confirmed the
HTML regenerated automatically with the correct, unaffected canonical totals (185/185, $0.2934)
-- the debug run's own output went to its own default path, not the canonical per-capability
report, so it didn't pollute the aggregate.

README updated: Quickstart now notes the auto-regeneration; repository structure section lists
`reports/`, `build_test_report.py`, `build_high_level_notebooks.py`, and `tests/high_level/`
(the last of these had been missing from the README despite existing since the prior session).

34/34 offline tests pass throughout every change in this entry.
